\section{Introduction and Problem Statement}
Sudoku is deceptively simple for humans to understand, but solving it programmatically on harder grids can quickly become a bottleneck in browser environments. When implemented entirely in client-side JavaScript, recursive search algorithms like depth-first backtracking often struggle with call-stack overhead and variable performance across different devices. On the other hand, writing a native desktop application in C++ gives great performance, but makes it harder to share and run without installation hurdles.

To get the best of both worlds, we built this project around a decoupled, two-tier architecture. All core game rules, grid representation, and recursive backtracking logic are written in modern C++ (C++17) using clean Object-Oriented principles. We then compile this backend into WebAssembly (Wasm) using Emscripten. This approach lets our C++ solver run directly inside any modern web browser at near-native speeds, while a lightweight HTML5, CSS Grid, and vanilla JavaScript frontend handles player interaction, real-time board validation, and animations.

\section{Scope and Feature Set}
We designed the game to be practical, responsive, and intuitive to play:
\begin{itemize}
    \item \textbf{Instant C++ Backtracking Engine:} Uses recursive Depth-First Search with search pruning to solve valid $9 \times 9$ boards in under 5 milliseconds.
    \item \textbf{On-Demand Puzzle Generation:} Generates fresh, solvable puzzles across three distinct difficulty tiers (Easy: 40 clues removed, Medium: 50 removed, Hard: 60 removed).
    \item \textbf{Smart Hint System:} Helps players when they get stuck. Instead of giving away the entire solution, it runs the solver in the background, deduces the correct number for the cell the player has currently selected (or picks an empty square), and fills it in with an amber highlight.
    \item \textbf{Live Conflict Detection \& Visual Feedback:} Checks rows, columns, and $3 \times 3$ boxes on every keystroke. Conflicting numbers instantly turn the grid border red and trigger a shake animation so mistakes are spotted right away.
    \item \textbf{Safe State Management (Reset vs. Clear):} Distinguishes between starting fresh (`Clear`, which wipes the board) and reverting user guesses (`Reset`, which restores the original starting puzzle clues).
    \item \textbf{Strict Clue Locking:} Starting clues are permanently marked read-only so players cannot accidentally overwrite given numbers during gameplay.
\end{itemize}

\section{Object-Oriented Architecture}
We organized the backend around core Object-Oriented Programming (OOP) concepts to keep the logic clean, modular, and easy to test.

\subsection{Class Design and Associations}
The backend consists of four primary components:
\begin{itemize}
    \item \textbf{Encapsulation (\texttt{Cell} and \texttt{Board}):} The \texttt{Cell} class encapsulates its value (strictly bounded between 0 and 9) and whether it is a fixed clue. The \texttt{Board} class owns the $9 \times 9$ matrix of cells, keeping direct grid modification private. External components must call \texttt{board.setCell()}, which guarantees that invalid values or attempts to alter fixed clues are rejected.
    \item \textbf{Abstraction \& Strategy Pattern (\texttt{SudokuSolver}):} Rather than coupling the solving algorithm directly to the board data, we defined an abstract base class \texttt{SudokuSolver} with a pure virtual method \texttt{virtual bool solve(Board\& board) = 0}. Both \texttt{BacktrackingSolver} (deterministic DFS) and \texttt{RandomGenerator} (randomized candidate order) inherit from this interface. This makes it straightforward to swap in alternative solving strategies (such as Dancing Links / Algorithm X) in the future without touching the rest of the application.
\end{itemize}

\subsection{Code Snippet: Abstraction \& Encapsulation}
The snippet below shows how the abstract interface decouples the algorithm while the board safeguards its internal state:

\begin{lstlisting}
class Board {
private:
    Cell grid[81]; // Encapsulated matrix
public:
    bool setCell(int index, int value) {
        // Guard against altering starting clues
        if (!grid[index].isFixed()) {
            grid[index].setValue(value);
            return true;
        }
        return false;
    }
};

// Abstract Solver Contract
class SudokuSolver {
public:
    virtual bool solve(Board& board) = 0; // Pure virtual function
    virtual ~SudokuSolver() {}
};

When the user requests a hint, JavaScript asks the C++ WebAssembly module to solve the current puzzle in the background, then extracts and renders just the target number:

    targetCell.classList.add("hint");
    targetCell.focus();

\section{System Communication and Workflow}
Rather than passing complex object references across the JavaScript and C++ runtime boundary, we adopted a clean, stateless communication protocol based on string serialization.

\begin{itemize}
    \item \textbf{Frontend UI Layer:} HTML and CSS Grid render the interactive board, while \texttt{app.js} captures user actions (typing digits, clicking buttons, using arrow keys) and runs instant conflict validation.
    \item \textbf{WebAssembly Boundary:} When the user clicks \textit{Solve} or \textit{Hint}, JavaScript converts the grid into an 81-character string (with \texttt{'0'} for empty squares) and passes it to the WebAssembly module. This string-based interface keeps memory management cleanly isolated, preventing memory leaks between the browser's garbage collector and C++ heap.
    \item \textbf{C++ Backend Layer:} Emscripten bindings unpack the string into a \texttt{Board} object and hand it to \texttt{BacktrackingSolver}. Once solved, the board is serialized back into an 81-character string and returned to JavaScript, which updates the DOM.
\end{itemize}

\section{Tools and Technology Stack}
\begin{itemize}
    \item \textbf{C++17:} Implements domain models, constraint validation, and recursive backtracking.
    \item \textbf{Emscripten SDK (\texttt{emsdk}):} Compiles the C++ source files into a compact WebAssembly module (\texttt{solver.wasm}) and generates the JavaScript loader (\texttt{solver.js}).
    \item \textbf{HTML5 / CSS3 / Vanilla JavaScript:} Provides the lightweight frontend, CSS Grid styling, input masking, and animations.
    \item \textbf{Python \texttt{http.server}:} Serves the project files locally during development with correct MIME types for WebAssembly, avoiding browser CORS restrictions.
\end{itemize}
